# cargo-dispatch

[🇺🇦 Українська](../../README.md) · [🇬🇧 English](README.en.md) · [🇫🇷 Français](README.fr.md) · [🇩🇪 Deutsch](README.de.md) · [🇪🇸 Español](README.es.md) · **🇰🇷 한국어** · [🇯🇵 日本語](README.ja.md) · [🇨🇳 简体中文](README.zh.md)

화물 차량 배차 시스템입니다. 운행을 계획하고, 실행에 넘기고, 운전자와 연락하며, 실제 진행 상황을 기록합니다. 주 개발 언어는 **Rust**입니다.

**안정 버전: [v0.2.0](https://github.com/RomanZavadaM/cargo-dispatch/releases/tag/v0.2.0).** 개발은 계속되며, 테스트 빌드는 [Releases](https://github.com/RomanZavadaM/cargo-dispatch/releases)에 있습니다.

## 구성

| 프로그램 | 사용자 | 플랫폼 |
|---|---|---|
| **Control** | 배차 담당자: 진행 중인 운행 관리 | Windows, macOS, Linux |
| **Planner** | 계획 담당자: 경로와 운행 패키지 작성 | Windows, macOS, Linux |
| **운전자 페이지** | 운전자, 설치 없이 아무 브라우저에서 | 휴대전화, 태블릿, 컴퓨터 |
| **Android용 Driver** | 운전자 | Android 8.0 이상 |
| **iPhone·iPad용 Driver** | 운전자 | iOS / iPadOS 17 이상 |
| **Addressing Gateway** | 인터넷을 통한 연결 | Linux 서버 |

진행 중인 운행의 사실 정보는 Control만이 관리합니다. Control은 운전자에게 페이지, 경로, 파일을 직접 제공하고 완료 표시, 위치, 첨부 파일을 받습니다. 중앙 운행 데이터베이스는 없습니다.

## 시작하기

1. 릴리스 페이지에서 압축 파일을 받아 풀고 **Control**을 실행합니다. Control 패키지에는 가상의 테스트 데이터(`local-browser-test-data`)가 들어 있습니다.
2. **“운행 추가”** → “기존 운행 열기”(운행 폴더 또는 Planner 패키지) 또는 “새 운행을 수동으로 만들기”.
3. **“운전자 연결하기”** → “이 컴퓨터”, “같은 Wi-Fi 네트워크” 또는 “어디서나 인터넷으로”.
4. **“다음 단계”** 영역의 링크를 운전자에게 전달합니다: “열기” 또는 “복사”.
5. 운전자는 링크를 브라우저에서 열거나 Driver 앱에 붙여 넣습니다.

## 기능

**Control**
- 여러 운행을 동시에 관리, 운행별 별도 창;
- Planner 패키지에서 가져오거나 수동으로 만든 운행; 상태는 로컬에 저장되고 재시작 후 복원됩니다;
- 미완료 지점 순서, 지도, 운전자의 최신 위치, 계획과 실적 비교;
- 운전자에게 파일 전송; 운전자로부터 파일, 사진, 동영상 수신;
- 로컬 네트워크의 컴퓨터 주소를 스스로 찾고, 연결 방식을 직접 끄지 않고 바꿀 수 있습니다;
- 오류 메시지는 인터페이스 언어로 표시되며, 위치 시각·파일 크기·지점 이름을 알기 쉽게 보여 줍니다.

**Planner**
- 주문 파일(JSON, 사람과 AI 공용) 또는 직접 입력; 적재 한도를 고려한 최대 3개의 경로안, 선택 후 운행에 반영; 입력 내용은 유지됩니다(v0.2.0 이후).
- 경로 초안: 좌표로 지점 추가, 삭제, 순서 변경; 초안은 재시작 후에도 유지됩니다;
- 직접 입력한 차량 제원으로 자체 Valhalla 서버를 통한 경로 미리보기와 도로선(모르는 값은 지어내지 않습니다);
- 화물과 계획 근거를 담은 운행 패키지(ZIP, 스키마 1.4) 내보내기; 기존 파일은 덮어쓰지 않습니다.

**운전자: 브라우저, Android, iPhone·iPad**
- 경로와 지도, 지점 완료 표시, 미완료 지점 순서 변경;
- 문서 받기; 파일, 사진, 동영상 보내기;
- 위치 전송; 앱에서는 백그라운드 전송도 가능하며 명시적으로 켜고 끄고, 재전송 대기열이 있습니다;
- 지점 완료 표시 전에 확인을 요청합니다. 앱에는 내비게이션 버튼, 파일의 지점 연결, 자동 갱신 화면, 연결이 없을 때의 이동 경로 보관(최대 500개 위치), 거부된 파일 표시 기능도 있습니다.

## 연결과 보안

- **이 컴퓨터**와 **로컬 네트워크** 방식은 암호화되지 않습니다(HTTP). 신뢰하는 네트워크에서만 사용하세요. 네트워크 접속은 저절로 켜지지 않으며 공유기 포트를 열지 않습니다.
- 비밀 코드가 든 링크로 운행에 접속합니다. 해당 운행의 운전자에게만 전달하세요.
- 휴대전화 브라우저는 보통 HTTPS, 즉 Gateway를 통해서만 위치 정보를 허용합니다.
- 휴대전화가 네트워크에서 Control에 접속하려면 컴퓨터 방화벽에서 프로그램을 허용하세요.
- **인터넷 연결:** HTTPS 리버스 프록시 뒤에 자체 Gateway를 둡니다. Control이 먼저 연결하므로 컴퓨터에 수신 포트가 필요 없습니다. Gateway는 운행, 문서, 미디어, 위치를 저장하지 않습니다. 기본 중계 한도는 요청당 64 MiB입니다(512 MiB까지 설정 가능).

## 지도와 경로

Control, Planner, 브라우저, Android의 지도는 [OpenStreetMap](https://www.openstreetmap.org/copyright)(© OpenStreetMap contributors)이며, iPhone·iPad에서는 Apple MapKit입니다. 지도 제공자는 기기의 IP 주소와 표시 영역을 볼 수 있습니다. 도로선에는 자체 Valhalla 서버가 필요합니다. 없어도 운행은 작동하며 도로선만 표시되지 않습니다.

## 아직 확인하지 않은 것과 제한

- Android 및 iPhone/iPad 앱은 실제 기기에서 시험하지 않았으며 에뮬레이터, 시뮬레이터, 자동 테스트로만 확인했습니다.
- 모바일 인터넷과 실제 네트워크의 Gateway는 자동 테스트로만 확인했습니다.
- 패키지는 서명되지 않았습니다. Android는 디버그 APK이고 iOS는 Apple 시뮬레이터용 빌드뿐입니다.
- Control을 다시 시작하면 운행과 연결을 직접 다시 켜야 합니다.
- 배차 담당자는 아직 지점을 편집하거나 완료 표시를 할 수 없습니다.
